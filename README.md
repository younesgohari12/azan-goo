# کیف پول Orbit — رابط کاربری (مرحلهٔ دوم)

فرانت‌اند مستقل کیف پول Orbit با React + TypeScript + Vite. این نسخه فقط رابط کاربری است: همهٔ داده‌ها و عملیات محلی و نمایشی‌اند و هیچ اتصالی به بک‌اند، دیتابیس، درگاه پرداخت، API بانکی، پیامک یا WebSocket وجود ندارد. صفحهٔ چت و بخش‌های دیگر پیام‌رسان هم در دامنهٔ این پروژه نیستند.

رابط فارسی و RTL است، فونت Vazirmatn (بستهٔ npm، بدون CDN) و ارقام با جداکنندهٔ هزارگان فارسی نمایش داده می‌شوند. تمام دارایی‌ها (فونت، آیکون‌ها) درون همین سورس‌اند.

## اجرا

```bash
npm install
npm run dev        # http://localhost:3000
npm run typecheck  # بررسی نوع‌ها
npm run build      # خروجی استاتیک در dist/
npm run preview    # پیش‌نمایش خروجی build روی پورت ۳۰۰۰
npm run package    # ساخت orbit-wallet-ui.zip بدون node_modules (شامل dist/)
```

روی پورت ۳۰۰۰ سرو می‌شود تا در سندباکس Base44 هم پیش‌نمایش بگیرد.

## چه چیزی در این مرحله ساخته شده است

### نمایش و جریان‌ها

- **نمای اصلی**: موجودی قابل استفاده با نمایش/پنهان‌کردن، موجودی در انتظار، چهار اقدام اصلی، و فعالیت‌های اخیر.
- **جریان‌های عملیات** (هر سه با یک ساختار مشترک):
  - افزایش اعتبار: ورود/انتخاب مبلغ → اعتبارسنجی → خلاصهٔ تأیید → **در حال پردازش** → نتیجهٔ موفق یا ناموفق → تلاش دوباره یا بازگشت.
  - انتقال: انتخاب گیرنده (جست‌وجو + تبدیل فهرست به خلاصهٔ گیرنده) → مبلغ و توضیح → مرور و تأیید → پردازش → نتیجه.
  - برداشت: انتخاب مقصد (accordion جزئیات) → مبلغ و نمایش کارمزد → تأیید → پردازش → نتیجهٔ «در انتظار».
- **تاریخچهٔ کامل**: جست‌وجو (نام، شناسه، توضیح، مبلغ)، فیلتر نوع (همه/افزایش اعتبار/انتقال/برداشت)، فیلتر وضعیت (همه/موفق/در انتظار/ناموفق)، گروه‌بندی روزانه، صفحه‌بندی محلی با «نمایش بیشتر»، حالت بدون نتیجه و پاک‌کردن فیلترها.
- **جزئیات تراکنش و رسید**: نوع، وضعیت، مبلغ، تاریخ و ساعت، طرف مقابل/مقصد، کارمزد و توضیح (فقط اطلاع مرتبط با همان نوع)، و کپی شناسهٔ پیگیری با تبدیل آیکون به تیک و پیام کوتاه.
- **حالت‌های خالی و بازخورد**: موجودی صفر، بدون تراکنش، بدون نتیجهٔ جست‌وجو، پردازش کوتاه (جای‌گیرندهٔ هم‌اندازهٔ رسید)، عملیات ناموفق، تلاش دوباره، toast و دیالوگ تأیید.
- **اعتبارسنجی**: پذیرش رقم فارسی و انگلیسی، مدیریت مبلغ خالی/صفر/نامعتبر/بیش از موجودی، جدایی نمایش مبلغ از مقدار عددی داخلی، پیام دقیق برای گیرندهٔ انتخاب‌نشده و جلوگیری از ثبت دوبارهٔ همان عملیات.

### حرکت

یک سیستم مشترک در `src/motion/tokens.ts` (بازخورد فوری ~۱۲۰ms، کنترل ~۱۸۰ms، پنل و مرحله ~۲۵۰ms، easing `cubic-bezier(0.22, 1, 0.36, 1)`):

- گذار جهت‌دار مراحل و صفحه‌ها، ورود اولیهٔ stagger روی چهار گروه اصلی فقط یک‌بار.
- «در حال پردازش» روی همان اقدام نمایش داده می‌شود؛ صفحه در loading نمی‌ماند و رسید جای‌گیرنده‌ها را با همان ابعاد نتیجه نگه می‌دارد تا اندازه نپرد.
- نتیجهٔ موفق با رسم کوتاه تیک و ورود گروهی رسید؛ نتیجهٔ ناموفق آرام (بدون لرزش فرم و بدون افکت جشن).
- تاریخچه: نتایج با crossfade عوض می‌شوند و کل فهرست از ابتدا انیمیت نمی‌شود؛ «نمایش بیشتر» فقط موارد جدید را با stagger محدود وارد می‌کند.
- تمام حرکت‌ها با `prefers-reduced-motion` و `MotionConfig reducedMotion="user"` سازگارند.

### دسترس‌پذیری

focus داخل پنل/دیالوگ نگه داشته می‌شود، Escape فقط لایهٔ رویی را می‌بندد و focus به کنترل قبلی برمی‌گردد؛ خطای مبلغ focus را به همان فیلد می‌برد؛ لایه‌ها روی هم انباشته نمی‌شوند؛ معادل لمسی hover وجود دارد و ناوبری با کیبورد کار می‌کند.

### تم تیره

تم تیره فقط با توکن‌ها کنترل می‌شود و صفحهٔ تنظیمات جدا ندارد. برنامهٔ میزبان می‌تواند آن را تعیین کند:

```js
document.documentElement.dataset.theme = 'dark' // یا 'light'
```

## مسیرهای تست (نمونه، بدون عملیات واقعی)

نقطهٔ شروع برای همهٔ مسیرها: موجودی نمونه **۲٬۴۵۰٬۰۰۰ تومان**. هیچ‌کدام از این کارها پول واقعی جابه‌جا نمی‌کند.

| مسیر | مراحل | نتیجهٔ مورد انتظار |
| --- | --- | --- |
| موفق | «افزایش اعتبار» → ۵۰٬۰۰۰ → ادامه → تأیید و پرداخت | کوتاه «در حال پردازش»، بعد تیک موفق و موجودی جدید **۲٬۵۰۰٬۰۰۰** |
| موفق (انتقال) | «انتقال» → سارا محمدی → ۱۰۰٬۰۰۰ → مرور و تأیید → تأیید و انتقال | رسید موفق و موجودی **۲٬۳۵۰٬۰۰۰** (فقط یک‌بار کسر می‌شود) |
| در انتظار | «برداشت» → مقصد و ۶۰٬۰۰۰ → ادامه → تأیید برداشت | نتیجهٔ «در انتظار تسویه»؛ موجودی به اندازهٔ مبلغ برداشت (۶۰٬۰۰۰) کم می‌شود، کارمزد از خود مبلغ کسر می‌شود |
| ناموفق + تلاش دوباره | آدرس را با `/?demo=failed` باز کنید، بعد یک افزایش اعتبار انجام دهید | نتیجهٔ ناموفق، موجودی بدون تغییر، دکمهٔ «تلاش دوباره» به گام تأیید برمی‌گردد |
| در انتظار برای همهٔ عملیات | `/?demo=pending` | همان مسیرها، نتیجهٔ «در انتظار» |
| موجودی صفر | برداشت به اندازهٔ تمام موجودی، یا `/?balance=0` | مبلغ ۰ و راهنمای «هنوز اعتباری در کیف پول نیست.» |
| بدون تراکنش | `/?empty=1` | فهرست خالی با راهنمای «هنوز تراکنشی ثبت نشده است.» |

پارامترهای آدرس فقط برای تست‌اند، در UI دیده نمی‌شوند و نام‌شان در `src/data/walletConfig.ts` نگه داشته می‌شود. `demo` هنگام اجرای عملیات خوانده می‌شود؛ `balance` و `empty` هنگام بارگذاری صفحه.

## ساختار

```
src/
  data/        دادهٔ نمونه، تنظیمات نمایشی و قواعد نمونهٔ عملیات (بدون وابستگی به UI)
  lib/         قالب‌بندی فارسی/تاریخ، عدد متحرک، media query، کلیپ‌بورد، پشتهٔ Escape، cx
  motion/      توکن‌ها و variantهای حرکت
  host/        محل اتصال به برنامهٔ میزبان
  components/  اجزای پایه: Icon، Amount، AmountField، Button، Sheet، ConfirmDialog، Toast، Skeleton، EmptyState، CopyField، …
  features/wallet/  نمای اصلی، تاریخچه، فیلترها، جزئیات و فرم‌های عملیات
  shell/       پوستهٔ سادهٔ پیش‌نمایش
```

جداسازی داده از UI:

- `src/data/walletData.ts` — فقط داده: موجودی، ۱۳ تراکنش نمونه، گیرنده‌ها، مقصدها.
- `src/data/walletConfig.ts` — فقط قواعد نمایشی: کارمزد، حد پایین، مبالغ پیشنهادی، مدت پردازش، وضعیت نتیجهٔ نمونه، اندازهٔ صفحهٔ تاریخچه.
- `src/data/walletRules.ts` — قاعدهٔ نمونهٔ تأثیر هر عملیات بر موجودی.
- `src/data/walletDemo.ts` — خواندن پارامترهای تست.

هیچ‌کدام قانون واقعی سرویس نیستند و هیچ‌جا داخل UI hardcode نشده‌اند. نقطه‌های جایگزینی با بک‌اند: همین فایل‌های `data/`، متد `submitOperation` در `WalletProvider`، و متد `WalletOperation` به‌عنوان ورودی.

قاعدهٔ موجودی (نمونه): افزایش اعتبار فقط با نتیجهٔ موفق اضافه می‌کند؛ انتقال در نتیجهٔ موفق «جمع = مبلغ + کارمزد» را کسر می‌کند؛ برداشت به اندازهٔ مبلغ برداشت کسر می‌شود (کارمزد داخل همان مبلغ است) و در نتیجهٔ ناموفق هیچ عملیاتی موجودی را دست نمی‌زند.

## اتصال به برنامهٔ میزبان

کیف پول هیچ وابستگی‌ای به میزبان ندارد و فقط از طریق `window.OrbitHost` با آن حرف می‌زند (`src/host/hostBridge.ts`):

```js
window.OrbitHost = {
  onWalletBack: () => router.back(),                 // کنترل بازگشت صفحهٔ اصلی
  onWalletEvent: (event) => analytics.track(event),  // { type, amount, status }
}
```

بدون میزبان، کیف پول مستقل کار می‌کند و زدن دکمهٔ بازگشت پیام کوتاهی نشان می‌دهد. تم توسط `document.documentElement.dataset.theme` تعیین می‌شود.

## اجرا در سندباکس Base44

`docker-compose.base44.yml` یک سرویس `node:22` با bind mount همین ریپو اجرا می‌کند؛ نصب وابستگی‌ها هنگام بالا آمدن و سپس `vite` روی `0.0.0.0:3000`.

- `__VITE_ADDITIONAL_SERVER_ALLOWED_HOSTS`: هاست‌های مجاز پیش‌نمایش را به Vite می‌دهد.
- `BASE44_PREVIEW_MODE=1`: در `vite.config.ts` فقط فایل‌واچر را روی polling می‌گذارد تا hot reload روی bind mount کار کند. اگر تعریف نشده باشد یا مقدار دیگری داشته باشد، رفتار پیش‌فرض Vite دست‌نخورده می‌ماند. هیچ منطق دیگری از برنامه به این متغیر وابسته نیست.

## نکته‌های شناخته‌شده

- **کپی شناسه** در پیش‌نمایش داخل iframe ممکن است به‌خاطر سیاست مجوز مرورگر انجام نشود؛ در آن حالت پیام «کپی نشد؛ شناسه را دستی بردارید.» نشان داده می‌شود و برنامه در حالت باز مستقل کپی را انجام می‌دهد.
- موجودی فقط در حافظهٔ React است؛ بارگذاری مجدد صفحه دادهٔ نمونهٔ اولیه را برمی‌گرداند.
