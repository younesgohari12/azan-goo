# کیف پول Orbit — رابط کاربری (مرحلهٔ اول)

فرانت‌اند مستقل کیف پول Orbit با React + TypeScript + Vite. این نسخه فقط رابط کاربری است: همهٔ داده‌ها و عملیات محلی و نمایشی‌اند و هیچ اتصالی به بک‌اند، دیتابیس، درگاه پرداخت، API بانکی، پیامک یا WebSocket وجود ندارد.

رابط فارسی و RTL است، فونت Vazirmatn (به‌صورت بستهٔ npm و بدون CDN) و ارقام با جداکنندهٔ هزارگان فارسی نمایش داده می‌شوند.

## اجرا

```bash
npm install
npm run dev        # http://localhost:3000
npm run typecheck  # بررسی نوع‌ها
npm run build      # خروجی استاتیک در dist/
npm run preview    # پیش‌نمایش خروجی build روی پورت ۳۰۰۰
npm run package    # ساخت orbit-wallet-ui.zip بدون node_modules (شامل dist/)
```

روی پورت ۳۰۰۰ سرو می‌شود تا در سندباکس Base44 هم پیش‌نمایش بگیرد.

## چه چیزی در این مرحله ساخته شده است

- **نمای اصلی**: سربرگ با عنوان «کیف پول» و کنترل بازگشت، موجودی قابل استفاده با نمایش/پنهان‌کردن و نمایش جداگانهٔ موجودی در انتظار، چهار اقدام اصلی (افزایش اعتبار، انتقال، برداشت، تاریخچه) و فعالیت‌های اخیر با نوع، تاریخ و ساعت، مبلغ ورودی/خروجی، وضعیت و امکان بازکردن جزئیات.
- **فرم‌های عملیات**:
  - افزایش اعتبار: کادر مبلغ، مبالغ پیشنهادی، خلاصهٔ مبلغ انتخاب‌شده، خلاصهٔ تأیید و نتیجه.
  - انتقال: انتخاب/جست‌وجوی گیرنده، مبلغ و توضیح اختیاری، خلاصهٔ تأیید و نتیجه.
  - برداشت: انتخاب مقصد، مبلغ، مبلغ دریافتی و کارمزد نمونه، تأیید و نتیجه.
- **فهرست کامل تراکنش‌ها** با فیلتر (همه، ورودی، خروجی، در انتظار) و گروه‌بندی روزانه، به‌همراه پنل جزئیات تراکنش.
- **حرکت**: یک سیستم مشترک با توکن‌های `src/motion/tokens.ts` (بازخورد فوری ~۱۲۰ms، کنترل ~۱۸۰ms، پنل و مرحله ~۲۵۰ms، easing `cubic-bezier(0.22, 1, 0.36, 1)`)، ورود اولیهٔ stagger روی چهار گروه اصلی فقط یک‌بار، گذار جهت‌دار مراحل، crossfade پنهان‌کردن موجودی و احترام به `prefers-reduced-motion`.

## ساختار

```
src/
  data/        دادهٔ نمونه و تنظیمات نمایشی (بدون هیچ وابستگی به UI)
  lib/         قالب‌بندی فارسی/تاریخ، هوک عدد متحرک، media query، cx
  motion/      توکن‌ها و variantهای حرکت
  host/        محل اتصال به برنامهٔ میزبان
  components/  اجزای پایه: Icon، Amount، AmountField، StatusBadge، Sheet، SummaryList، …
  features/wallet/  نمای اصلی، فهرست تراکنش‌ها، جزئیات و فرم‌های عملیات
  shell/       پوستهٔ سادهٔ پیش‌نمایش
```

جداسازی داده از UI: `src/data/walletData.ts` فقط داده (موجودی، تراکنش‌ها، گیرنده‌ها، مقصدها) و `src/data/walletConfig.ts` فقط قواعد نمایشی (کارمزد، حد پایین، مبالغ پیشنهادی، وضعیت نتیجهٔ عملیات) است. هیچ‌کدام از این مقادیر قانون واقعی سرویس نیستند؛ نقطهٔ جایگزینی با پاسخ بک‌اند همین دو فایل و متد `submitOperation` در `WalletProvider` است.

## اتصال به برنامهٔ میزبان

کیف پول هیچ وابستگی‌ای به میزبان ندارد و فقط از طریق `window.OrbitHost` با آن حرف می‌زند (`src/host/hostBridge.ts`):

```js
window.OrbitHost = {
  onWalletBack: () => router.back(),            // کنترل بازگشت صفحهٔ اصلی
  onWalletEvent: (event) => analytics.track(event), // { type, amount, status }
}
```

بدون میزبان، کیف پول مستقل کار می‌کند و زدن دکمهٔ بازگشت پیام کوتاهی نشان می‌دهد.

## اجرا در سندباکس Base44

`docker-compose.base44.yml` یک سرویس `node:22` با bind mount همین ریپو اجرا می‌کند؛ نصب وابستگی‌ها هنگام بالا آمدن و سپس `vite` روی `0.0.0.0:3000`.

- `__VITE_ADDITIONAL_SERVER_ALLOWED_HOSTS`: هاست‌های مجاز پیش‌نمایش را به Vite می‌دهد.
- `BASE44_PREVIEW_MODE=1`: در `vite.config.ts` فقط فایل‌واچر را روی polling می‌گذارد تا hot reload روی bind mount کار کند. اگر تعریف نشده باشد یا مقدار دیگری داشته باشد، رفتار پیش‌فرض Vite دست‌نخورده می‌ماند. هیچ منطق دیگری از برنامه به این متغیر وابسته نیست.

## مرحلهٔ دوم

تعاملات تکمیلی، صفحهٔ جزئیات تراکنش به‌شکل کامل و پرداخت نهایی در مرحلهٔ دوم روی همین ساختار اضافه می‌شوند. نقطه‌های آماده برای ادامه: `Transaction`/`WalletSnapshot` در `src/data/types.ts`، متد `submitOperation`، و پنل `Sheet` برای گام‌های بیشتر.
