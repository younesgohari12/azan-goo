# گزارش یکپارچه‌سازی با افزونه وردپرس

این سند مرجع وضعیت اتصال فرانت‌اند به REST API افزونهٔ `snappshop-automation/v1` است.
سورس و مستندات بک‌اند در اختیار این نسخه نبوده؛ بنابراین همهٔ مسیرها در یک فایل متمرکز
(`src/api/endpoints.ts`) تعریف شده‌اند و در حالت پیش‌فرض پنل با دادهٔ نمونه کار می‌کند.

## قواعد رعایت‌شده

- هیچ درخواستی خارج از `src/api/client.ts` انجام نمی‌شود (احراز هویت، خطا و transport یک‌جا).
- احراز هویت با کوکی نشست وردپرس + هدر `X-WP-Nonce`؛ هیچ توکنی در فرانت‌اند ذخیره نمی‌شود.
- در حالت `live`، هر خطای HTTP/شبکه به پیام فارسی و وضعیت Error/Empty قابل‌بازیابی تبدیل می‌شود.
- بعد از هر mutation، کوئری‌های مرتبط با TanStack Query باطل و مجدداً دریافت می‌شوند.
- مبالغ فقط به تومان نمایش داده می‌شوند؛ تبدیل واحد انجام نمی‌شود.
- تاریخ‌ها فقط برای نمایش شمسی می‌شوند؛ در درخواست‌ها ISO میلادی ارسال می‌شود.

## Endpointهای مصرف‌شده (در انتظار تأیید با مستندات بک‌اند)

| قابلیت | متد و مسیر | صفحه |
| --- | --- | --- |
| خلاصهٔ داشبورد | `GET /dashboard/summary?store_id&range` | داشبورد |
| فعالیت‌های اخیر | `GET /activity?limit&type` | داشبورد، تاریخچه، موجودی |
| فهرست فروشگاه‌ها | `GET /stores` | فروشگاه‌ها، تاپ‌بار، تنظیمات |
| جزئیات فروشگاه | `GET /stores/:id` | فروشگاه‌ها |
| بررسی اتصال | `POST /stores/:id/check` | فروشگاه‌ها، تنظیمات |
| فهرست محصولات | `GET /products?search&sync_status&match_status&category&stock_state&mismatch&page&per_page&sort&order` | محصولات، قیمت‌گذاری، موجودی |
| جزئیات محصول | `GET /products/:id` | Drawer محصول |
| ویرایش محصول | `PATCH /products/:id` (`wc_price`, `wc_stock`) | Drawer محصول |
| عملیات گروهی | `POST /products/bulk` (`ids`, `operation`, `mode`, `value`) | محصولات، قیمت، موجودی |
| تاریخچهٔ قیمت | `GET /pricing/history?product_id&limit` | قیمت‌گذاری، Drawer |
| خلاصهٔ موجودی و قوانین | `GET /inventory/summary?store_id` | موجودی |
| سفارش‌ها | `GET /orders?search&status&from&to&page&per_page` | سفارش‌ها |
| جزئیات سفارش | `GET /orders/:id` | جزئیات سفارش |
| وضعیت همگام‌سازی | `GET /sync/status?store_id` | مرکز همگام‌سازی |
| اجرای همگام‌سازی | `POST /sync/run` (`store_id`, `scope`, `mode`) | مرکز همگام‌سازی |
| فهرست Jobها | `GET /jobs?status&type&page&per_page` | Jobها |
| جزئیات Job | `GET /jobs/:id` | Jobها |
| لغو Job | `POST /jobs/:id/cancel` | Jobها، مرکز همگام‌سازی |
| تلاش مجدد Job | `POST /jobs/:id/retry` | Jobها |
| قوانین اتوماسیون | `GET/POST /automations`, `PATCH /automations/:id` | اتوماسیون |
| فعال/غیرفعال قانون | `POST /automations/:id/toggle` | اتوماسیون |
| اجرای دستی قانون | `POST /automations/:id/run` | اتوماسیون |
| تخفیف‌ها | `GET /discounts` | تخفیف‌ها |
| گزارش‌ها | `GET /reports?type&from&to` | گزارش‌ها |
| اعلان‌ها | `GET /notifications`, `POST /notifications/read` | اعلان‌ها، تاپ‌بار |
| تنظیمات | `GET /settings`, `PUT /settings` | تنظیمات |

## قابلیت‌های متصل (در حالت mock کامل تست‌شده، در حالت live نیازمند تأیید مسیرها)

- نمایش و فیلتر محصولات، جست‌وجو، مرتب‌سازی، انتخاب چندگانه، ویرایش تکی و گروهی قیمت/موجودی
- مقایسهٔ قیمت و موجودی دو سیستم، پیش‌نمایش قبل از اعمال و تأیید نهایی
- مدیریت سفارش‌ها با فیلتر وضعیت/تاریخ و صفحهٔ جزئیات با Timeline
- مرکز همگام‌سازی با پیشرفت زنده، لغو عملیات و تاریخچهٔ اجراها
- پایش Jobها با فیلتر، جزئیات خطاها، لغو و تلاش مجدد
- ساخت/ویرایش/فعال‌سازی/اجرای قوانین اتوماسیون با Trigger و Actionهای محدود
- تنظیمات ۱۲ بخشی با اعتبارسنجی، تشخیص تغییرات ذخیره‌نشده و تأیید تغییرات حساس
- اعلان‌ها (خواندن تکی/همه)، گزارش‌ها با بازهٔ زمانی و خروجی CSV/JSON

## شکاف‌های یکپارچه‌سازی (Integration Gaps)

| # | قابلیت | وضعیت | اقدام لازم |
| --- | --- | --- | --- |
| 1 | تأیید مسیر و شکل پاسخ همهٔ endpointها | مسیرها موقتی‌اند (`endpoints.ts`) | ارائهٔ مستندات OpenAPI یا سورس کنترلرها |
| 2 | اتصال فروشگاه جدید (`POST /stores`) | فرم اتصال غیرفعال؛ پیام امنیتی نمایش داده می‌شود | endpoint اتصال + قواعد اعتبارسنجی توکن |
| 3 | ویرایش تنظیمات هر فروشگاه | فقط نمایش | endpoint `PATCH /stores/:id` |
| 4 | ایجاد/ویرایش/حذف تخفیف | فقط نمایش | endpointهای تخفیف |
| 5 | تغییر وضعیت سفارش در اسنپ‌شاپ | عمداً ساخته نشد | مستندسازی endpoint (در حال حاضر پشتیبانی نمی‌شود) |
| 6 | تاریخچهٔ اختصاصی موجودی | از فعالیت‌های نوع `stock` استفاده می‌شود | endpoint تاریخچهٔ موجودی |
| 7 | فهرست دسته‌بندی محصولات | فهرست ثابت در UI | endpoint دسته‌بندی‌ها |
| 8 | لاگ کامل Job | فقط آرایهٔ `errors` نمایش داده می‌شود | endpoint لاگ‌ها |
| 9 | حذف قانون اتوماسیون | گزینه در منو غیرفعال است | endpoint `DELETE /automations/:id` |
| 10 | خروجی سمت سرور | خروجی CSV/JSON در مرورگر از پاسخ گزارش ساخته می‌شود | در صورت نیاز، endpoint خروجی |
| 11 | مجوزها و نقش‌ها | فقط نمایش؛ بررسی نهایی در بک‌اند | endpoint قابلیت‌های کاربر |
| 12 | تست خودکار | ندارد | افزودن Vitest/Playwright در گام بعد |

## حالت نمایشی

اگر `window.snappShopAutomation` توسط افزونه تزریق نشود یا `VITE_API_MODE=live` نباشد،
کلاینت مرکزی transport نمونه را به‌صورت dynamic import بارگذاری می‌کند:

- داده‌ها در `src/api/mock/seed.ts` و رفتار در `src/api/mock/transport.ts` است.
- عملیات (ویرایش قیمت/موجودی، اجرای Sync، لغو Job، ساخت قانون، ذخیرهٔ تنظیمات) در حافظه
  اعمال می‌شوند تا جریان‌های UI واقعاً قابل تست باشند؛ هیچ داده‌ای به وردپرس ارسال نمی‌شود.
- نشان «حالت نمایشی» در سایدبار و بنر داشبورد قابل بستن است تا کاربرها اعداد ساختگی را
  واقعی تصور نکنند.
- در build نهایی افزونه (`npm run build:plugin`) این transport در باندل اولیه وجود ندارد و
  فقط در صورت فراخوانی mock بارگذاری می‌شود؛ برای انتشار production باید
  `apiMode: 'live'` تزریق شود.
